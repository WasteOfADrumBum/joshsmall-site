# Release record: portfolio closeout (November 2026)

Closes the current release of onesmall.company. No redesign and no new product features. Optional ideas are in
[ROADMAP.md](../ROADMAP.md).

Everything below was checked by an agent on 2026-11-02 unless it says "owner". Owner confirmations are quoted
as the owner gave them; the agent did not verify them.

## Release scope

The site as deployed from `main` at `5f0a849` (PRs #1 to #27), plus the closeout PR that adds this file:

- CI workflow (`.github/workflows/ci.yml`): lint, typecheck, unit tests and production build on every push to
  `main` and every pull request. Adds a `typecheck` script (`next typegen && tsc --noEmit`), because
  `tsc --noEmit` alone fails on a clean checkout (the global `LayoutProps` type is generated by Next).
- Fix: visitors with reduced motion got a hydration error (React #418, logged in production) because the hero's
  Pause button was left out of the client render but not the server render. It is now hidden with CSS
  (`motion-reduce:hidden`). First noted in PR #22, confirmed on a production build before the fix.
- Fix: `/api/contact` returned 500 for a JSON body that is not an object (`null`, an array, a string). It now
  returns 400 (`asContactBody`, with a unit test).
- Fix: the contact form showed the browser's raw text ("Failed to fetch") on a network error and could spin
  forever on a stalled connection. It now gives up after 20 s and shows a plain message for network errors and
  timeouts. Server messages are shown as before.
- Privacy note under the contact form (see "Data and privacy").
- `.env.example` uses a placeholder delivery address instead of the owner's personal one.

### Contact form and abuse protection

- Validation: shared by the form and the API (`src/lib/contact.ts`): required fields, length limits
  (100/200/4000), email shape, control characters removed from the name (it goes into the subject).
- Abuse protection: a honeypot field only. There is no rate limit and no Vercel Firewall configuration (the
  Firewall API returned "config not found"). Resend's free plan caps sending at 100 emails a day, so a flood
  would not cost money but could block real messages until the next day. See "Manual checks".
- Error handling: 400 for bad input, 503 when env vars are missing, 502 when Resend rejects; the visitor never
  sees provider details.
- Logging: only `error.name` / `error.message` from Resend and booleans for missing env vars. No message
  content, names or addresses are logged by the app.
- Owner confirmation: "contact emails arrive successfully." No real send was repeated, because nothing in this
  closeout changes the server's send path (the API change only rejects bodies that previously crashed).

### Data and privacy

- Collected: the name, email and message a visitor types into the contact form. They go to Resend, which
  emails them to the owner; Resend also keeps its own email log. Nothing is stored by the site.
- Hosting: Vercel serves the site and handles requests, so it sees IP addresses and request metadata as any
  host does.
- Cookies, analytics, tracking: none. No third-party scripts, styles or fonts load in the browser (fonts are
  self-hosted by `next/font`, and the CSP allows only `'self'`). Outbound links (LinkedIn, GitHub, project
  sites) are plain links.
- Disclosure: a one-sentence note under the form says what is sent, where, why, and that there are no cookies
  or analytics. A full privacy policy page was not added: with no tracking and one form, the note covers it.
